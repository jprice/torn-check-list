# Torn API policy change: 2026-11-10

**Documentation-only update, November 10, 2026.** This records Torn's forum announcement supplied by the repository owner and the official live API documentation. It does **not** certify that this repository currently makes any particular request or that a deployed version has been audited. Recheck the official API docs before new integrations because limits and behavior can change.

## Effective immediately (announcement dated 2026-11-10)

| Selection | New global cache |
| --- | --- |
| `market -> itemmarket` | **1 hour** (was 30 seconds) |
| `market -> properties` | **1 hour** (was 30 seconds) |
| `market -> rentals` | **1 hour** (was 30 seconds) |
| `company -> companies` | **1 hour** (was 30 seconds) |
| `torn -> bounties` | **5 minutes** (was 30 seconds) |
| `user -> bounties` | **5 minutes** (was 30 seconds) |

- **`user -> bazaar` is private and owner-only:** a key with **at least Limited Access** can read **the key owner's own bazaar**, not other players' bazaars. Insufficient access yields an **empty array** rather than a new response shape. An empty result must not be interpreted as reliable evidence that another player's bazaar is empty.
- **A one-hour global cache is not a one-hour refresh promise.** The underlying response can repeat until the global cache updates. Display source/cache timestamps where available and avoid claims of real-time freshness.
- **Global caches cannot be bypassed** by distinct keys, changing request parameters or adding a timestamp. Torn's separate *service cache* can last up to 30 seconds; the normal service-cache behavior must not be confused with these selections' **global** cache windows.
- **API use does not authorize scraping.** Torn's announcement reiterates that scraping, unauthorised automation and efforts to work around these restrictions remain prohibited. Do not substitute page scraping for newly restricted selections.

## Limits / safety

- **100 requests per minute per Torn player across all keys** belonging to that player. Other scripts, mobile tools and servers using that player's keys share the budget. Additional keys do **not** grant additional per-player quota.
- Torn documents **5,000 requests per minute per IP address** for services that have accumulated many keys; it may enforce this separately from the per-player quota. **Never use multiple IPs/servers to bypass** Torn's IP cap. Contact Torn staff when approaching it.
- Handle Torn error **5** (user rate limit) with backoff; error **8** means an IP block. Stop or quarantine invalid/disabled keys rather than retrying aggressively. Minimize unnecessary calls and honor available cache/source timestamps.
- Changes may be made without notice. These limits are not permission to automate player actions or to collect more personal data than necessary.

## What is *not* established by this announcement

The announcement **does not say** that every Torn API endpoint has a one-hour cache. In particular, do not transfer this new rule to `market/auctionhouse`, `market/auctionhouselisting`, `user/inventory`, `user/itemmarket`, `user/equipment`, `user/log` or faction receipt/roster data without endpoint-specific documentation. Names that both contain “itemmarket” need to be checked under their full endpoint scope. Likewise, a successful API request is not proof that the underlying data is fresh.

## Repository-specific impact

Legacy checklist application: its README describes three API calls every 30 seconds, plus more calls for custom tasks. That historical rate is not a guarantee of combined player quota safety if other tools use the same player's keys. No listed market/bazaar/company/bounty selection has been confirmed from this documentation; no polling or application behavior was changed.
